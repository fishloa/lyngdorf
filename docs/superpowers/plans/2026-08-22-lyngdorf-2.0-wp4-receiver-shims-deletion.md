# Lyngdorf 2.0 — WP4 (`LyngdorfReceiver`, Shims, 1.x Deletion) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Plan 4 of 5** for the lyngdorf 2.0.0 release. Source of truth:
`docs/superpowers/specs/2026-08-21-lyngdorf-2.0-design.md` at commit `b10576d`
— read §12's WP4 entry, §7 (the migration table), D9 (§11) and §2.2 before
starting. This plan implements **WP4 only**. It assumes Plans 1–3 have
landed on the `2.0` branch: `streaming/` on aiohttp, `rio/` extracted with
`RioClient` and the dialect tables, and `lyngdorf/controls.py` +
`lyngdorf/components.py` with their factories (`build_volume`,
`build_trims`, `build_lipsync`, `build_zone_b`, `build_player`,
`build_remote`) and the `NowPlayingEngine` protocol.

**Goal:** Build `LyngdorfReceiver` (the entire 2.0 public receiver surface,
spec §2.2) beside the intact 1.x surface; land the D9 deprecation-shim
layer *on the new class*; **only then** delete the 1.x receiver surface and
port the behavioural test suite — so that no commit, at any point, has the
old surface gone with nothing standing in for it.

**Architecture:** `LyngdorfReceiver` (`lyngdorf/receiver.py`) is pure
assembly plus cached state: it owns a `LyngdorfApi` (the WP2 `RioClient`
subclass that still carries the streaming engine — see "What did not
survive contact", item 1), builds the WP3 components from `ModelConfig` via
the WP3 factories, selects the WP2 dialect per model, and defines the
wire-callback methods (value conversion only) that route device replies
into component `_update_*` calls and its own flat state. The shim layer is
a mixin (`lyngdorf/_compat.py`) the class inherits — one file, deleted
wholesale in 2.1 — with every shim registered in module-level name sets so
completeness is testable, not asserted. The 1.x deletion is staged as
port-the-tests-as-a-copy first, then a near-pure-deletion commit.

**Tech Stack:** Python 3.11 · Poetry · pytest + pytest-asyncio ·
mypy 1.19.1 (pinned binary) · ruff · black. No new dependencies.

### What did not survive contact with the actual code

1. **`api.py` survives WP4 as the internal engine; `streaming/poll.py` is
   still not created here.** Spec §4's final layout has no `api.py`, but
   deleting it in WP4 would force the poll-loop move *and* the port of
   ~208 test references in `streaming_test.py`/`streaming_transport_test.py`
   into this already-largest package. `LyngdorfReceiver` therefore owns a
   `LyngdorfApi` — which is simultaneously the `RioClient` (wire writes,
   dispatch) and the `NowPlayingEngine` behind `Player` (Plan 3's ruling).
   The poll-loop relocation into `streaming/poll.py` rides WP5's session
   plumbing, which edits `_poll_now_playing` anyway. Flagged for Plan 5.

2. **The spec's test-port scope ("the `basic_wiring_test.py` port") is
   incomplete — four more test files import the 1.x receiver classes.**
   Measured: `remote_key_test.py` (478 lines, imports all ten subclasses),
   `disconnect_guarantee_test.py` (174 lines, `Receiver` +
   `async_create_receiver`), `streaming_test.py` (a `Receiver`-facing
   section, ~lines 1418–1520) and `streaming_transport_test.py`
   (`TestReceiverCapabilities` ~376–480 plus a
   `register_notification_callback` block ~665). Task 5 ports all of them;
   the deletion cannot go green otherwise.

3. **The four internal boundaries hold, but boundary 3 only holds if the
   port is staged as a copy.** Ported tests must run against
   `LyngdorfReceiver` *before* the deletion commit (otherwise the port and
   the deletion are one unreviewable 5000-line commit). But
   `async_create_receiver` still returns the old classes until the deletion
   commit — so the ported copy constructs `LyngdorfReceiver(host, model)`
   directly (construction is side-effect free), and the handful of
   factory-path tests port only in the deletion commit, alongside the
   factory rewrite. Cost: one commit where ~4,800 lines of tests exist
   twice under two filenames. Accepted — it is what makes the deletion
   commit reviewable as a deletion.

4. **`LyngdorfModel.config` cannot be deleted, only de-published.** §7
   lists `config` among the removed-from-public members, but §4
   simultaneously rules "internal code reads `model.config` directly".
   Resolution: the `config` property survives with an "internal — not part
   of the public API" docstring; the *delegate methods* are deleted and
   every internal call site retargets to `model.config.*` (Task 5
   enumerates them by grep). The §2.9 inverse-assertion test therefore
   asserts non-resolution only for members that genuinely stop existing.

5. **The `has_*_feature()` shims cannot live in `_compat.py`.** They are
   methods on `LyngdorfModel` (§7: "shim (on LyngdorfModel)"), and enum
   classes cannot inherit a late mixin. They stay in
   `lyngdorf/models/__init__.py` as a clearly-fenced
   `# --- D9 shims, delete in 2.1 ---` block, each warning and delegating
   to `self.config.*`, and they are listed in `_compat.py`'s registry so
   the completeness test still covers them. "Shims live in one module"
   becomes "one module plus one fenced block", recorded here.

6. **`convert_decibel` is duplicated for two commits.** Task 1 copies it
   into `receiver.py` (spec §4: it "lives beside" the receiver); the
   `device.py` original keeps serving the 1.x surface until Task 5 deletes
   it. Two copies of a 13-line pure function for two commits, then one.

class TestOnChange:
    def test_on_change_fires_dedupes_and_unsubscribes_idempotently(self):
        """spec §2.2/§9 item 10: duplicate registration collapses to one
        entry; the returned unsubscribe is idempotent."""
        r, _ = _prepared(LyngdorfModel.MP_60)
        calls: list[int] = []

        def cb() -> None:
            calls.append(1)

        unsub = r.on_change(cb)
        again = r.on_change(cb)  # duplicate: collapses to one entry
        r._api._process_event("!VOL(-100)")
        assert calls == [1]  # fired once, not twice
        unsub()
        again()  # second unsubscribe of the same cb: no-op, no error
        unsub()  # and repeat: still a no-op
        r._api._process_event("!VOL(-110)")
        assert calls == [1]

class LyngdorfReceiver:
    """A Lyngdorf A/V processor or integrated amplifier.

    <the write-semantics paragraph from the module docstring, verbatim,
    so it renders on the class in IDEs>
    """

    def __init__(self, host: str, model: LyngdorfModel) -> None:
        self._host = host
        self._model = model
        self._api = LyngdorfApi(host, model)
        self._dialect = _DIALECTS[model]

        # Components and controls - structural capability (design §5):
        # built once, from ModelConfig, via the WP3 factories.
        self._volume = build_volume(self._api)
        self._trims = build_trims(self._api)
        self._lipsync = build_lipsync(self._api)
        self._zone_b = build_zone_b(self._api)
        self._player = build_player(model, self._api)
        self._remote = build_remote(self._api)

        # Flat cached state (design §2.2's non-component members).
        config = model.config
        self._audio_inputs = config.audio_inputs
        self._video_inputs = config.video_inputs
        self._stream_types = config.stream_types
        self._sources = CountingNumberDict()
        self._sound_modes = CountingNumberDict()
        self._room_perfect_positions = CountingNumberDict()
        self._voicings = CountingNumberDict()
        self._name: str | None = None
        self._power_on: bool | None = None
        self._max_volume: float | None = None
        self._muted: bool | None = None
        self._source: str | None = None
        self._sound_mode: str | None = None
        self._audio_input: str | None = None
        self._video_input: str | None = None
        self._audio_info: str | None = None
        self._video_info: str | None = None
        self._streaming_source: str | None = None
        self._room_perfect_position: str | None = None
        self._voicing: str | None = None
        self._notification_callbacks: list[Callable[[], None]] = []

        # <the now-playing/play-mode -> on_change wiring block from
        #  device.py:131-149 moved verbatim, including the deliberate
        #  position-asymmetry comment ("do not 'fix' it by adding
        #  position here too") - gated on self._player is not None
        #  instead of has_streaming_feature()>
        if self._player is not None:
            self._api.register_now_playing_callback(self._now_playing_changed)
            self._api.register_play_mode_callback(self._play_mode_changed)

    # -- identity / lifecycle ---------------------------------------------

    @property
    def host(self) -> str:
        """The device's host/IP - required at construction, so typed
        honestly (was str | None in 1.x)."""
        return self._host

    @property
    def model(self) -> LyngdorfModel:
        return self._model

    @property
    def name(self) -> str | None:
        """The device-reported name, or None before the first reply."""
        return self._name

    def connected(self) -> bool:

    async def connect(self) -> None:
        """Register wire callbacks and open the :84 connection.

        Keeps the 1.x sequence exactly (design §8): register -> connect
        (paced setup burst, monitor, poll start for streaming models all

**The two measured shapes, stated before any code (D9, both measured —
do not re-derive them):**

1. **Sync→async members get a sync-bodied shim that returns the
   coroutine — never `async def`.** Both shapes trip mypy's
   `unused-coroutine` equally, but unawaited at runtime the sync-bodied
   shim fires one `DeprecationWarning` where an `async def` shim fires
   **zero** — a silent no-op. This is *not* the property-setter hazard in
   new clothes: calling an async function returns a coroutine without
   executing anything — nothing enqueues, no `asyncio.Event` is touched —
   until the caller awaits it on the loop. Someone will ask; point them
   here and at D9.
2. **Relocation read shims are read-only properties and must stay that
   way.** Measured against `MagicMock(spec=...)` fixtures: the mock
   replaces the descriptor wholesale, so a fixture write is allowed and
   the shim body never runs *with or without* a shim — settability would
   buy fixtures nothing, and it would require a property setter, the
   exact thing D9 carves out.

**The two carve-outs — nothing here may "complete" the layer:**
- No shim for the 18 property setters (self-enforcing removal; a

  exists to remove).
- No shim for the reused names — **`volume` and `lipsync` only**, by the
