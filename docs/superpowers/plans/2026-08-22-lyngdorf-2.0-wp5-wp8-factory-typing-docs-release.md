**Plan 5 of 5** for the lyngdorf 2.0.0 release. Source of truth:
`docs/superpowers/specs/2026-08-21-lyngdorf-2.0-design.md` at commit `20c3b9c`
— read §2.1, §8, §12's WP5–WP8 entries, §13, and D1/D3/D8/D9 (§11) before
starting. This plan implements **WP5, WP6, WP7 and WP8**, plus the recording
(not the execution) of the 2.1 shim deletion. It assumes Plans 1–4 have
landed on the `2.0` branch: `streaming/` on aiohttp with `StreamingClient`,
`rio/` extracted, `controls.py`/`components.py`, `receiver.py` with
`LyngdorfReceiver`, `_compat.py` with the D9 shim mixin, and the 1.x
receiver surface deleted.

**Goal:** Close the library. WP5 gives 2.0 its front door — `create_receiver`
with end-to-end session ownership, the discovery split, and the module-level
1.x names renamed behind their own shims — and finishes the §4 module layout
by retiring `api.py`. WP6 makes the whole package strict and proves the
`py.typed` marker actually ships. WP7 writes the documents the Home Assistant
integration migrates from. WP8 verifies on real hardware and releases 2.0.0
by `CLAUDE.md`'s tag-driven process.

**Architecture:** `lyngdorf/discovery.py` (spec §4) holds all four
module-level entry points and is the only place with knowledge of *which*
transport answers which question: `discover_model` over raw TCP `:84`,
`discover_ssdp_location` over UDP (the one retained, bounded, deliberately
documented `run_in_executor` — D8), `fetch_device_serial` over pure aiohttp,
and `create_receiver` assembling a `LyngdorfReceiver`. Exactly two of them
take a `session`; the asymmetry is the design (§2.1) and is asserted by a
test so nobody "completes the set". Session ownership is decided once, at
`LyngdorfReceiver.__init__` (`_owns_session = session is None`), and the
`StreamingClient` — today a local variable inside the poll coroutine — is
hoisted to a receiver-owned field so `disconnect()` has something to close.
The module-level shims live in the `__init__.py` module `__getattr__`
alongside WP4's `Receiver` alias, registered in `_compat.py` so the §7-row
completeness test covers them.

**Tech Stack:** Python 3.11 · Poetry · pytest + pytest-asyncio ·
aiohttp (`>=3.0.0`, a range) · mypy 1.19.1 (pinned binary) · ruff · black ·
`gh` CLI. No new dependencies.

### What did not survive contact with the actual code

1. **WP5's shims-first requirement is achievable, but not by the shape WP4
   used — and following WP4's shape literally produces a test that cannot
   go green.** Measured against the WP4 exit state (Plan 4 Task 5 Step 4):
   `lyngdorf/__init__.py` reaches WP5 with a *literal eager import*,
   `from .device import async_create_receiver, async_find_receiver_model,
   async_get_device_serial`, and a module `__getattr__` that handles only
   `Receiver`. A module-level `__getattr__` is consulted **only when normal
   attribute lookup fails** (PEP 562). So a shim branch added for
   `async_create_receiver` while that import line still exists is
   *unreachable* — `lyngdorf.async_create_receiver` resolves to the real
   function and never warns. An implementer writing the shim test first
   (WP4's habit, and the right habit) will watch it fail, add the shim,
   and watch it fail again, with nothing wrong with either.

   The resolution keeps the guarantee the rule exists for — *no commit has
   an old name gone with nothing standing in for it* — and drops the
   assumption that "add the shim" and "remove the old definition" must be
   different commits:

   - **Commit A** creates `discovery.py`, and in `__init__.py` **removes
     the three eager imports and adds the three `__getattr__` branches in
     the same edit**. `lyngdorf.async_create_receiver` never stops
     resolving; it transitions from a real function to a warning shim in
     one atomic step. The shim tests go green here. `lyngdorf/device.py`
     is untouched and its definitions still exist, unused.
   - **Commit B** deletes `lyngdorf/device.py`.

   Task 6 verifies the guarantee mechanically rather than asserting it:
   `getattr(lyngdorf, name)` resolves at `HEAD~1`, at `HEAD`, and at every
   commit in between. That check is the actual deliverable of the rule.

2. **`Player`'s transport writes do not use the injected session at all —
   they allocate and destroy an entire `aiohttp.ClientSession` per press.**
   Plan 1 Task 8 Step 3 ports the one-shot path to
   `async with aiohttp.ClientSession() as session:` inside `_one_shot`, and
   `_get_status(session=None, …)` routes every write there because
   `Player` passes no `StreamingClient` (correctly — spec §8 forbids
   routing writes through the poll lock). The result contradicts §2.1's
   promise that the injected session "is used for all `:8080`
   streaming-module HTTP", and on Home Assistant it means a `ClientSession`
   (connector, DNS resolver, cookie jar) constructed and torn down every
   time a user presses pause. Task 3 fixes it with a routing flag rather
   than by threading a raw session through twelve helper signatures — see
   its Interfaces block. The lock is still not taken: that constraint is
   §8's load-bearing one and this change does not touch it.

3. **The poll loop's `StreamingClient` is a local variable, and its
   `finally: session.close()` cannot survive being hoisted.** Today
   (`api.py:1303`) the client is created inside `_poll_now_playing` and
   closed in the coroutine's `finally` with the comment "The task is
   cancelled on disconnect; without this the kept-alive socket would linger
   on the device." Session plumbing requires the opposite: the client must
   outlive the poll task (transport writes share it, reconnect reuses it,
   and `disconnect()` must be able to close an *owned* session it has a
   reference to). Two consequences, both deliberate:
   - The `finally` close is deleted and `disconnect()` closes instead.
   - Power-gated polling (`set_power_state` stops the poll on power-off)
     therefore no longer closes the socket. **aiohttp's connector reaps
     idle keep-alive connections on its own** (`keepalive_timeout`,
     default 15 s) — which `http.client` never did, and is precisely why
     1.x needed the manual close. Connector settings are not touched
     (§8: they would be global on an injected session). The 1.x comment's
     evidence moves to `disconnect()` so the history survives, and WP8's
     hardware gate measures socket count across a power cycle rather than
     trusting this paragraph.

4. **The consumer-contract fixture contains zero module-level names**, so
   WP5's three shims get **no** consumer-contract coverage — the §7-row
   completeness test is their only gate. Verified against
   `tests/fixtures/consumer_contract_ha.json`: every one of its nine
   categories holds receiver members;
   `shimmed_methods_already_async` is `async_connect`/`async_pause`/… and
   does not contain `async_create_receiver` or `async_get_device_serial`,
   which a Home Assistant config flow must call. The fixture is a *measured*
   artefact and this is a measurement gap, not a design choice. Two
   consequences: Task 13's release gate adds a one-off manual check of the
   consumer's config flow against §7's module-level rows, and Task 15
   records that the module-level shims' 2.1 deletion scope comes from §7,
   not from the fixture.

5. **Submodule import paths are not shimmable, and the repo's own examples
   use one.** `examples/model.py` does
   `from lyngdorf.device import async_find_receiver_model`. `__init__.py`'s
   `__getattr__` cannot rescue that; Commit B's deletion of `device.py`
   turns it into `ModuleNotFoundError`. Spec §12's WP7 entry does not
   mention `examples/` at all. Task 6 fixes the examples as part of the

   explicit **import paths** row, because a consumer or its test suite may

6. **`diagnostics.async_probe_device_capabilities` → `probe_capabilities`

```python
"""Discovery: three transports, three functions (spec §2.1, §8, D8).

The split's whole point is that a caller who already knows the UPnP
location never takes the UDP hop, so these tests exercise each half
independently and then the compose path, exactly as the two real callers
do (Home Assistant's discovered flow; its manual-entry flow).

import asyncio
import inspect
import socket

import aiohttp
import pytest
from aiohttp import web

from lyngdorf.discovery import (
    _lookup_model,
    discover_model,
    discover_ssdp_location,
    fetch_device_serial,
)
from lyngdorf.models import LyngdorfModel

_DESCRIPTION_XML = """<?xml version="1.0"?>
<root xmlns="urn:schemas-upnp-org:device-1-0">
  <device>
    <friendlyName>Lyngdorf MP-60</friendlyName>
    <serialNumber>ABC123def</serialNumber>
  </device>
</root>"""


@pytest.fixture
async def description_server(aiohttp_server):
    """Serves the UPnP description document, counting requests."""
    hits: list[str] = []

    async def handler(request: web.Request) -> web.Response:
        hits.append(request.path)
        return web.Response(text=_DESCRIPTION_XML, content_type="text/xml")

    async def not_found(request: web.Request) -> web.Response:
        return web.Response(status=404)

    app = web.Application()
    app.router.add_get("/desc.xml", handler)
    app.router.add_get("/missing.xml", not_found)
    server = await aiohttp_server(app)
    server.hits = hits          # type: ignore[attr-defined]
    return server


class TestFetchDeviceSerial:
    async def test_owned_session_path(self, description_server):
        """No session supplied: the function creates and closes its own."""
        url = str(description_server.make_url("/desc.xml"))
        assert await fetch_device_serial(url) == "abc123def"

    async def test_injected_session_is_used_and_never_closed(self, description_server):
        """spec §8: an injected session is used for the description fetch
        and is never closed by the library."""
        url = str(description_server.make_url("/desc.xml"))
        async with aiohttp.ClientSession() as session:
            assert await fetch_device_serial(url, session=session) == "abc123def"
            assert not session.closed
        assert description_server.hits == ["/desc.xml"]

    async def test_non_200_returns_none(self, description_server):
        url = str(description_server.make_url("/missing.xml"))
        assert await fetch_device_serial(url) is None

    async def test_unreachable_returns_none_rather_than_raising(self):
        """The helpers' never-raises contract (spec §8) covers this path:
        a config flow calls it on a host it is still validating."""
        assert await fetch_device_serial("http://127.0.0.1:1/desc.xml") is None

    async def test_malformed_xml_returns_none(self, aiohttp_server):
        async def handler(request):
            return web.Response(text="<not-xml", content_type="text/xml")

        app = web.Application()
        app.router.add_get("/desc.xml", handler)
        server = await aiohttp_server(app)
        assert await fetch_device_serial(str(server.make_url("/desc.xml"))) is None

    async def test_no_udp_on_this_path(self, description_server, monkeypatch):
        """The point of the split: reaching the HTTP half must not touch
        UDP. A socket() call of any kind fails this test."""
        def _boom(*args, **kwargs):
            raise AssertionError("fetch_device_serial opened a raw socket")

        monkeypatch.setattr(socket, "socket", _boom)
        url = str(description_server.make_url("/desc.xml"))
        assert await fetch_device_serial(url) == "abc123def"


class TestDiscoverSsdpLocation:
    async def test_returns_location_header(self):
        """A real UDP responder on loopback - the executor hop runs."""
        loop = asyncio.get_running_loop()
        sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
        sock.bind(("127.0.0.1", 0))
        port = sock.getsockname()[1]

        def _respond() -> None:
            data, addr = sock.recvfrom(4096)
            assert b"M-SEARCH" in data
            sock.sendto(
                b"HTTP/1.1 200 OK\r\nLOCATION: http://127.0.0.1:8008/desc.xml\r\n\r\n",
                addr,
            )

        responder = loop.run_in_executor(None, _respond)
        try:
            location = await _search_against(port)
            assert location == "http://127.0.0.1:8008/desc.xml"
        finally:
            await responder
            sock.close()

    async def test_no_reply_returns_none_within_the_timeout(self):
        """Bounded: sock.settimeout(timeout) stops the thread, and the
        wait_for(timeout + 1) stops the await. Neither is optional - see
        the comment at the hop."""
        started = asyncio.get_running_loop().time()
        assert await discover_ssdp_location("127.0.0.1", timeout=0.5) is None
        assert asyncio.get_running_loop().time() - started < 3.0

    @pytest.mark.parametrize("fn", [discover_model, discover_ssdp_location])
```

```python
    "ST: urn:schemas-upnp-org:device:MediaRenderer:2\r\n"
    "\r\n"
).encode()


async def discover_ssdp_location(host: str, timeout: float = 5.0) -> str | None:
    """Unicast SSDP M-SEARCH to a known host, returning its UPnP
    description URL (the LOCATION header), or None.

    UDP only - no HTTP, no session. Callers that already know the
    location (Home Assistant's own SSDP cache gives it as
    `ssdp_location`) skip this function entirely and go straight to
    `fetch_device_serial`; that avoidability is the point of the split.

    Deliberately takes NO session parameter: this speaks UDP, and a
    session here would misstate what it does (spec §2.1).
    """

    def _search() -> str | None:
        sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM, socket.IPPROTO_UDP)
        sock.settimeout(timeout)
        try:
            sock.sendto(_SSDP_MSEARCH, (host, _SSDP_PORT))
            data, _ = sock.recvfrom(4096)
            for line in data.decode(errors="replace").splitlines():
                if line.lower().startswith("location:"):
                    return line.split(":", 1)[1].strip()
        except (OSError, TimeoutError):
            pass
        finally:
            sock.close()
        return None

    # ------------------------------------------------------------------
    # This is the library's ONE run_in_executor, and it is deliberate.
    # Do not "fix" it into an asyncio datagram endpoint.
    #
    # Ruled in spec D8 on evidence from Home Assistant (#50): of the 86
    # libraries behind platinum-tier integrations, 17 use run_in_executor,
    # to_thread or a thread pool - several for exactly this class of
    # blocking socket call. `xknx/io/util.py:93` offloading
    # socket.gethostbyname is the direct parallel; aioshelly offloads
    # address resolution, brother SNMP engine setup, androidtvremote2 a
    # cert-chain load. The practical `async-dependency` bar is "nothing
    # blocks the event loop", not "no thread ever".
    #
    # The hop is bounded twice - sock.settimeout(timeout) stops the
    # thread, wait_for(timeout + 1) stops the await - discovery-time
    # only, and avoidable: a caller with an ssdp_location calls
    # fetch_device_serial directly and never reaches here. HA owns SSDP
    # scanning centrally (46 integrations declare ssdp: matchers), so
    # this must not be grown either; it serves manual entry, which exists
    # precisely for the devices HA's scanner did not see.
    # ------------------------------------------------------------------
    loop = asyncio.get_running_loop()
    try:
        return await asyncio.wait_for(
            loop.run_in_executor(None, _search), timeout=timeout + 1
        )
    except (TimeoutError, OSError):
        _LOGGER.debug("SSDP search to %s failed", host)
        return None


async def fetch_device_serial(
    location: str,
    *,
    session: aiohttp.ClientSession | None = None,
    timeout: float = 5.0,
) -> str | None:
    """Fetch the UPnP description XML at `location` and extract the
    device serial. Pure HTTP via aiohttp - no UDP anywhere on this path.

    An injected session is used and never closed (spec §8); with none
    supplied the function creates one for the single request and closes
    it. Returns None on any network or parse failure rather than raising:
    a config flow calls this against a host it is still validating.
    """
    http = session if session is not None else aiohttp.ClientSession()
    try:
        async with http.get(
            location,
            timeout=aiohttp.ClientTimeout(total=timeout + 1),
            headers={"Connection": "close"},
        ) as resp:
            if resp.status != 200:
                return None
            xml_text = (await resp.read()).decode(errors="replace")
    except (TimeoutError, OSError, aiohttp.ClientError):
        _LOGGER.debug("Failed to fetch UPnP description from %s", location)
        return None
    finally:
        if session is None:
            await http.close()

    try:
        root = ElementTree.fromstring(xml_text)
    except ElementTree.ParseError:
        _LOGGER.debug("Failed to parse UPnP XML from %s", location)
        return None
    ns = {"d": "urn:schemas-upnp-org:device-1-0"}
    serial_el = root.find(".//d:device/d:serialNumber", ns)
    if serial_el is not None and serial_el.text:
        return serial_el.text.strip().lower()
    return None
```

Three behaviour-preservation points, all measured against
`device.py:1835–1938`:
- `timeout + 1` is 1.x's arithmetic, kept byte-for-byte (spec §8: "keeping
  1.x's arithmetic, not adopting the number written here").
- `.strip().lower()` on the serial is 1.x's; a config flow's unique_id
  depends on it.
- `Connection: close` on a one-shot description fetch matches 1.x's
  `http.client` behaviour and keeps the device from holding an idle slot
  (#29/#31) when the caller injected a long-lived shared session.

Note in passing: 1.x's `_fetch_xml` had `conn` unbound in its `finally`
when `HTTPConnection(...)` raised, so a construction failure surfaced as

```python
async def create_receiver(
    host: str,
    model: LyngdorfModel | None = None,
    *,
    session: aiohttp.ClientSession | None = None,
) -> LyngdorfReceiver:
    """Create (but do not connect) a LyngdorfReceiver.

    With model=None, probes the device over :84 to identify it.
    Raises UnsupportedModelError if the reply names no supported model,
    TimeoutError/OSError on connection failure (propagated, as today).

    between creation and connect().

        if model is None:

    return LyngdorfReceiver(host, model, session=session)
```

```python
        self, path_and_query: str, timeout: float
```
